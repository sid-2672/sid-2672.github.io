01

Real-Time Voice Agent (Jarvis)

Full-duplex voice agent, <500ms latency. An asyncio triple-loop architecture streams Deepgram STT/TTS around a Groq Llama 3.1 token stream — feels like a phone call, not a chatbot with a microphone bolted on.

asyncioDeepgramGroq Llama 3.1
↗
Problem
Minimizing perceived latency in a cascaded speech → LLM → speech pipeline, where the dominant cost is serialization between stages, not any single model's inference time.
Approach
Three concurrent loops (listen / think / speak) coordinated by lock-free thread-safe queues; LLM tokens stream directly into speech synthesis instead of waiting for full generation.
Engineering hurdle
An adaptive TTS flush policy (punctuation-boundary or 30-character triggers) trading time-to-first-audio against natural prosody, plus an RMS noise gate and minimum-utterance filter to reject false barge-in from background noise. Also had to work around a Linux ALSA/PulseAudio bug where the mic would initialize successfully and capture zero bytes.
Result
<500ms end-to-end response, <300ms perceived latency to first audio.
02

Self-Healing Video Analytics Pipeline

People-counting system running YOLOv11 + BoT-SORT as distributed worker processes under a supervisor that detects and restarts crashed or frozen workers — built to run unattended for days, not to win a benchmark.

YOLOv11BoT-SORTOpenCV
↗
Problem
Long-running unattended perception systems fail quietly — a frozen worker looks identical to a healthy one from the outside.
Approach
A central supervisor process monitors and auto-restarts crashed or frozen workers. Directional entry/exit counts are derived from tracker trajectories using line-crossing gate logic over persistent object identities, not raw per-frame detections.
Engineering hurdle
Exposing live CPU/GPU/memory telemetry alongside throughput, so degradation is visible before it becomes an outage instead of after.
Note
The self-healing/supervisor pattern here is the same one behind the 5-stream RTSP pipeline I run at nhance.ai — this is the personal, from-scratch version, built independently to go deeper on the reliability side.
03

Multimodal Document QA

Document QA service with per-modality ingestion — native PDF text, row-wise Excel parsing, OCR for scanned images — behind /upload and /query REST endpoints, containerized with Docker.

FastAPIMilvusGemini
↗
Problem
A single ingestion path can't handle PDFs, spreadsheets, and scanned images equally well.
Approach
The ingestion stage auto-detects file type and adapts: Tesseract OCR for images, row-wise parsing for Excel, direct extraction for digital PDFs — then embeds into Milvus for retrieval.
Note
Same category of system as the RAG assistant I run in production over 10k+ documents at nhance.ai, built independently to go deeper on the ingestion side specifically.
04

Financial Chatbot

An agent that writes and executes real Python against your portfolio data instead of guessing numbers — LangChain + Gemini 2.5 Flash with explicit anti-hallucination guardrails.

LangChainGeminiStreamlit
↗
Problem
LLMs are unreliable at arithmetic; most "chat with your data" demos quietly hallucinate numbers.
Approach
Pandas dataframes are treated as tools the agent can call — it writes actual filter/aggregate code against Holdings and Trades data and executes it, so a wrong answer traces back to bad data, not a hallucinated one.
Guardrail
Explicit instruction to refuse out-of-scope questions rather than answer generically, keeping the agent scoped to what it can actually verify.

Research Direction

Where the engineering
turns into a question.

My interest sits somewhere between the method and the deployment: how detection and tracking models actually behave under real constraints — limited compute, several concurrent streams, processes that have to stay up for days without anyone watching them — and how much you can make them faster and more reliable without quietly giving up accuracy.

Most of what's on this page came from shipping a system first and getting curious about the "why" underneath it second, not the other way around. That's probably the honest description of where I am right now: an engineer who keeps finding a research question hiding under a deployment problem.

Areas I keep returning to

Computer Vision & Video Understanding Real-Time / Low-Latency Systems Efficient Inference & Edge Deployment Multi-Object Tracking Multimodal Document Understanding Retrieval-Augmented & Agentic LLM Systems
01 How much accuracy do you actually give up making a detection/tracking model edge-deployable — and is that floor fixed, or a function of how carefully you optimize the graph?
02 For a RAG system, is p95 latency actually the right thing to optimize, or just the easiest one to measure? What would it mean to measure whether retrieved context is right, not just fast?
03 Adaptive per-modality ingestion — OCR here, direct parsing there — gets you pretty far on multimodal documents. Where does that stitched-pipeline approach actually break, and is that the point where a real multimodal model earns its cost?
04 Long-running, unattended perception systems fail differently than benchmark runs do. What would it take to actually define "reliable" for a system that has to stay correct for weeks, not for one held-out test set?
Publications

IEEE ESCI 2024

Image Processing Based Traffic Surveillance

S. Prabhu, et al. — full author order pending confirmation from IEEE Xplore

Problem
Manual enforcement of two-wheeler traffic law is limited in coverage and inconsistently applied. This project asked whether commodity surveillance footage alone is enough to detect a violation and attribute it to a specific vehicle.
Dataset
5,000+ traffic-surveillance frames, co-collected and manually annotated (Roboflow) for helmet use, triple-riding, and mobile-phone use while riding.
Method
A custom convolutional network for multi-violation classification, coupled to a downstream license-plate localization and character-extraction stage — so a detected violation resolves to an identifiable vehicle, not just a flagged frame.
Result
92% F1-score on held-out annotated frames. Accepted and published in the IEEE ESCI 2024 proceedings, indexed in IEEE Xplore.
Code
Not public — this was a final-year academic project; the codebase sits with the institution rather than a personal repository.
